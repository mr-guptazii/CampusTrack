# CampusTrack — Setup Guide

CampusTrack is a Flutter 3.x + Firebase attendance manager with offline
support (Hive), analytics (fl_chart), a bunk calculator, timetable, and
notifications. This document gets the generated source tree in this folder
into a state you can open in Android Studio and run.

## 0. What's already here

Everything under `lib/`, the `android/` Gradle configuration, `firestore.rules`,
and `pubspec.yaml` is complete, hand-written Dart/Gradle — no placeholders
except `lib/firebase_options.dart`, which **must** be regenerated for your
own Firebase project (step 3).

Hive models are stored as plain `Map<String, dynamic>` (via each model's
`toJson`/`fromJson`) rather than `@HiveType` code-generated adapters, so
**no `build_runner` step is required** — `flutter pub get` is enough.

## 1. Prerequisites

- Flutter 3.19+ (`flutter --version`)
- Android Studio (Giraffe+) with the Android SDK (API 34) and an emulator or device
- A Google account for the Firebase console
- Node.js (only needed for the `firebase-tools` CLI used in step 3)

## 2. Scaffold native platform folders

This drop contains `lib/`, `pubspec.yaml`, `android/build.gradle.kts`,
`android/app/build.gradle.kts`, `android/app/src/main/AndroidManifest.xml`, the
Kotlin `MainActivity`, and Firestore config — but not the Gradle wrapper
binaries or `ios/`/`web/` folders, which Flutter generates locally and
shouldn't be hand-authored. From this project root run:

```bash
flutter create --platforms=android --org com.campustrack --project-name campustrack .
```

This fills in `android/gradlew`, `android/gradle/wrapper/`,
`android/local.properties`, and (if you want them) `ios/`/`web/` — without
overwriting the `lib/`, `pubspec.yaml`, or the Gradle config files already
provided, since those already exist and `flutter create` does not clobber
existing files it doesn't own.

## 3. Create the Firebase project

1. Go to the [Firebase console](https://console.firebase.google.com) and create a project, e.g. `campustrack-app`.
2. Enable **Authentication** → Sign-in method → turn on **Email/Password** and **Google**.
3. Enable **Firestore Database** → start in production mode (the rules below lock it down).
4. Install the CLI tooling once:
   ```bash
   npm install -g firebase-tools
   dart pub global activate flutterfire_cli
   ```
5. From the project root, log in and wire the project to your app:
   ```bash
   firebase login
   flutterfire configure --project=campustrack-app
   ```
   Select the `android` platform and package name `com.campustrack.campustrack`
   (must match `applicationId` in `android/app/build.gradle.kts`). This
   **overwrites** `lib/firebase_options.dart` with your real keys and drops
   `android/app/google-services.json` in place automatically.

## 4. Deploy Firestore security rules

The rules in `firestore.rules` restrict every document to its owning `uid`.
Deploy them with:

```bash
firebase deploy --only firestore:rules
```

(`firebase.json` already points at `firestore.rules` / `firestore.indexes.json`.)

## 5. Install packages and run

```bash
flutter pub get
flutter run
```

Or open the folder in Android Studio (`File → Open`), let it index, pick a
device/emulator, and press **Run**.

## 6. First launch

- Register a new account (email/password or Google) — a `users/{uid}` doc is
  created automatically.
- The app seeds 5 demo subjects (Data Structures, DBMS, Operating Systems,
  Computer Networks, Mathematics) with realistic attendance the first time
  a user has none, so Dashboard/Analytics/Bunk Calculator aren't empty.
- Mark attendance offline (airplane mode) to see local-first behavior; it
  syncs to Firestore automatically once connectivity returns.

## Project structure

```
lib/
├── main.dart                # Firebase/Hive/notifications bootstrap, MultiProvider
├── app.dart                 # MaterialApp.router + theme wiring
├── core/                    # constants, Material 3 theme, date/bunk-math utils, services
├── models/                  # Subject, AttendanceRecord, TimetableEntry, UserModel
├── providers/                # AuthProvider, SubjectProvider, AttendanceProvider, TimetableProvider
├── repositories/             # FirebaseRepository (Firestore), LocalRepository (Hive)
├── screens/                  # splash, auth, dashboard, subjects, attendance, timetable, analytics, settings
├── widgets/                   # subject_card, attendance_button, percentage_indicator, analytics_chart, timetable_tile
└── firebase_options.dart      # regenerated by flutterfire configure
```

## Notes & known limitations

- **Notifications**: `flutter_local_notifications` schedules the 8 PM daily
  reminder and per-class 10-minutes-before reminders; Android 13+ requires
  the runtime `POST_NOTIFICATIONS` permission, which is requested on first
  launch. Exact alarms rely on `SCHEDULE_EXACT_ALARM` (declared in the
  manifest) — some OEM devices require the user to grant this manually in
  system settings.
- **CSV export**: writes to the app's external storage directory (or app
  documents dir as a fallback) rather than the shared `Downloads/` folder,
  since writing directly to `Downloads` on Android 10+ requires the
  `MediaStore` API. The exact saved path is shown in the confirmation
  snackbar.
- **iOS**: the Dart code is platform-agnostic, but this drop only wires up
  Android natively. Run `flutter create --platforms=ios .` and
  `flutterfire configure` again with iOS selected if you need it.
- **Offline conflict resolution**: subjects/timetable entries compare
  `updatedAt`; attendance records compare `timestamp` — the newer write
  wins on sync, per-record/per-subject (last-write-wins).
